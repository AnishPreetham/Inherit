Know what you can trust in code you inherited.

Inherit is an agent that runs an unfamiliar Python repository in a sandbox, finds the tests that fail intermittently and the exact test that causes it, checks repairs by re-running them, and documents behavior only from what it actually observed. Everything it reports links to a recorded run.

The problem

Inherited code, no map

Authors have moved on, documentation is thin, and nobody is sure what the code really does.

Tests you can't trust

Some tests fail only sometimes. A red build might be a bug or just noise, so people re-run CI until it's green.

Plausible isn't proven

AI tools write tests and docs that look right but were never checked against the running program.

How it works

Eight stages. Repository code only ever runs inside an isolated container with no network access.

    Principles

    Evidence over plausibility

    Every test, claim and repair is backed by a recorded execution with an ID you can open. Model explanations are labeled as model-generated.

    No single trust score

    Stability, behavior coverage, repairs and documentation are reported separately. A suite can be stable but shallow, or broad but flaky.

    Limits stated plainly

    "Passed 20/20" means no failures under the recorded seeds and environment, not "always deterministic." Open uncertainties are listed in every report.

    Built with

    NVIDIA Nemotron, large

    The reasoner: diagnoses why a test is order-dependent, proposes a targeted patch, and writes documentation from recorded observations.

    NVIDIA Nemotron, small

    The worker: high-volume, latency-sensitive calls such as proposing inputs to probe each function.

    Nebius Token Factory

    OpenAI-compatible inference for both roles. Each report shows call counts, tokens and latency per model.

    Demo projects

    Seven small projects, each built to show a different part of Inherit. Open a pre-computed report instantly, or run the analysis live.
